# RUM / Field Core Web Vitals (2026-06-11)

Google ranks on FIELD data (CrUX), we only have lab (Lighthouse). Close the loop:
collect real-user LCP/INP/CLS/TTFB/FCP per site, ship to the existing
OTel→Prometheus pipeline, visualize p75 (Google's threshold percentile).

## Design
1. **Client**: `web-vitals` lib (handles prerender/bfcache correctly — we use
   speculation rules, hand-rolled observers would double-count). Lazy-loaded
   client island in the public layout; queue metrics, flush via
   `navigator.sendBeacon('/api/vitals')` on visibility hidden. Sampling via
   `NEXT_PUBLIC_VITALS_SAMPLE` (default 1.0). Zero PII: host, path, metric,
   value, device (mobile/desktop), connection type only.
2. **Endpoint** `/api/vitals`: zod-validated, per-IP rate-limited, records into
   OTel histograms (`web_vitals_lcp` ms, `_inp` ms, `_ttfb` ms, `_fcp` ms,
   `_cls` value×1000) with explicit CWV-aligned bucket boundaries. Reuses the
   existing OTLP metrics export — no new infra; no-op when OTel disabled.
3. **Cardinality guard**: path label normalized (strip query, lowercase,
   ≤100 chars) + per-replica cap of 500 unique paths, overflow → `_other`.
   Device/connection labels are tiny enums.
4. **Grafana**: RUM row in the CMS dashboard — p75 LCP/INP/CLS by host with
   Google "good" thresholds as reference lines.
5. **Verify**: endpoint unit behavior; live: post beacons → metric visible in
   Prometheus; e2e page visit emits beacon (playwright network assertion).
